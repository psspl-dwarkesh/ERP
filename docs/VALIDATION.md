## Identity pass, 3 November 2026

This pass fixed defects that made the redesign still read as generic, then re-measured every surface. Checks ran against a fresh production build served on a new preview port, because a preview started before an edit serves stale HTML and CSS and produces false readings.

| Check | Result and evidence limit |
| --- | --- |
| Display font actually loaded | Barlow Condensed was declared in 14 rules but never imported, so headings rendered in a fallback. Added to the single Google Fonts import in `product.css`. Verified through `document.fonts` and a canvas width probe (the headline measures differently from the same string in the generic fallback face) |
| Palette coherence | 623 cool-blue declarations inherited from the rejected concept were remapped to the mineral/record/copper ramps at matching relative luminance, so contrast ratios were preserved rather than guessed. Rendered-DOM scan reports residual cool-blue: 0 |
| Legibility floor | 299 declarations below 11 px raised to an 11 px floor. Minimum measured rendered font size is 11 px on all twelve surfaces |
| Text contrast | 87 real failures dominated by a `#7b8494`-derived muted tone at 2.9:1 used in about 290 places. Applied a contrast ladder for body tones against the actual composited ancestor background. Measured failures: 0 (target 4.5:1 body, 3:1 large) |
| Guard against over-correcting | An early unscoped pass also darkened light text on ink surfaces, producing dark-on-dark sidebar and entry labels. That regression was reverted from the untouched copy and re-run with dark-surface selectors excluded plus lightness guards. The corrected files are what is verified here |
| Browser chrome | Selection, scrollbars (standard and WebKit), caret, placeholder, control accent, focus ring, underline offset and tabular numerals are themed from the palette in `brand-refresh.css`; `theme-color` corrected from the rejected `#16392f` to `#172320`; an SVG favicon of the brand monogram was added |
| Generic patterns removed | Decorative eyebrow/kicker labels and duplicated numbering removed from the entry cover, dispatch header, connected-work header and service-commitments panel. Two ambient decorative circles on the cover were replaced by one drafting registration mark |
| Entry motion | The job route gained a scale plate that animates with the active stop. Record changes settle with a short transform and the record ID resolves its letter-spacing; both run only under `prefers-reduced-motion: no-preference` and reuse the existing easing curve |
| Layout integrity | A geometry check on every surface reported zero body overflow and zero element overflow, and the expected heading on each of the twelve routes. A pseudo-element bracket proposed for the cover collided with the active-record block and cover footer, so it was removed rather than left to overlap |
| Desktop-width rendering | The in-app browser window is fixed at 525×553 and cannot be resized, so each surface was re-measured inside a same-origin iframe whose own width drives its media queries. All twelve routes at 1440×900 and 1280×800, plus the entry and dashboard at 1920×1080 and four routes at 390×844: no document-level horizontal overflow, no unintended element overflow, minimum rendered text 11 px, zero contrast failures, zero residual cool-blue, Barlow Condensed reported loaded and the expected heading on every route |
| Loading placeholder | The dashboard's lazy-load placeholder was measured at 1440, 1280, 900 and 390 by mounting its markup against the built stylesheet, because on a local server the module resolves too fast to observe: its rows stay inside the panel and inside the viewport at every width, and the narrow layout drops the secondary line rather than squeezing it |
| Generic-pattern sweep | 23 `eyebrow` labels sat above headings in the module screens; 11 restated the heading or the sidebar grouping and were removed, and one was reduced to its identifier. All are now square, verified two ways: the built CSS carries the grouped override after the earlier rules, and the audit page reports zero rounded elements larger than a data mark on every route. Circles remain only where they mark data: legend dots, status dots and chart points |
| Dead styles from rejected concepts | Two superseded generations still carried rules: the rejected marketing landing page (`landing`, `landing-nav`, `landing-hero`, `hero-*`, `art-*`, `blueprint-panel`, `panel-*`, `floating-card`, `float-*`, `project/material/service-float`, `vertical-strip`, `workflow-*`, `landing-cta`, `preview-mini`, `preview-bars`, `landing-footer`) and the first KPI dashboard (`metrics-strip`, `operational-alert`, `alert-symbol`, `section-label`, `live-dot`, `dot-separator`, `attention-icon`, `button.ghost`). 1,279 lines across `product.css` (102,721 to 85,189 bytes) and `brand-refresh.css` were deleted, plus six comma-branch selectors pruned to their live terms. | Checklist mark finish | The guard also caught a rendered control the earlier geometry sweep missed: the payroll visit checklist box was still 3 px rounded with the rejected concept's cool `#f5faff` fill, because a class selector outranks the `span` override. `brand-refresh.css` now squares it explicitly and gives checked/unchecked paper tones from the record ramp, so measured rounded chrome is zero on every route |
| Geometry measured by size, not tag | The circle exemption no longer depends on the element happening to be an `<i>`: a mark of 8 px or less in both dimensions is treated as a legend or status dot, everything larger must be square. That removed the last false positive (a 5 px view indicator written as a `span`) without loosening the rule |
| Re-verification after the sweep | All twelve routes at 1440×900 and all twelve at 1280×800 on the final build: no document overflow, no unintended element overflow, 11 px minimum text, zero contrast failures, zero residual cool-blue, zero rounded chrome, Barlow loaded, expected heading on every route, and no console error or warning entries |
| Harness corrections made during the desktop pass | Two false results were traced to the harness, not the design. A hidden document freezes CSS animations at time zero, and `fill-mode: both` then holds the `from` opacity, so the active record block measured invisible and its copper text reported 1.8:1; animations are now settled to their base style before measuring, which is the steady state a user sees. A wide record table inside `.table-scroll` was reported as 26 overflowing elements; that container scrolls by design (`overflow-x: auto`, 1072 px of content in a 996 px box), so geometry under a scrollable ancestor no longer counts as a fault. Both rules were verified before the results above were recorded |
| Verification limit | These are computed-style and geometry measurements, not visual judgments. Screenshots were unavailable in this host, so the desktop pass confirms correctness of box model, size and contrast; aesthetic quality at wide viewports was not visually reviewed |

## Inventory count and subcontract pass, 3 November 2026

## Exit and handover pass, 3 November 2026

E2E-12 was the last journey with no screen. HR gains a fourth tab built around the one fixture that already held company property.

| Check | Result and evidence limit |
| --- | --- |
| Screen built | HR → Exit & handover presents EMP-0091's resignation as a six-line checklist — item, reference, owner, date, what has to be true, state and closing event — over a three-counter exception plate and a gate that refuses closure while anything is open. It ends in a closed record with a zero report, or in a refusal that names each open line |
| The leaver was chosen, not invented | Priya Menon was already in the fixtures as the calibration custodian, the owner of the company-held calibrator AST-0086 and the named owner of approved order PO-0112 whose 09 Nov delivery falls before her 14 Nov exit. The exit uses those records rather than a synthetic leaver, because an offboarding checklist only means something when the things on it exist elsewhere in the system. | A list item is not a closing event | "Mark the instrument returned" is refused with its reason, and the line clears only through a posted custody event that names the receiver and the condition it came back in. The same rule holds in the other direction: once the identity is deactivated, "Reopen her account to finish" is refused, because a provisioned identity is not switched back on to satisfy a checklist. Observed strings from the driven machine: "Recovery is a custody event with a receiver, a condition and a time…" and "A deactivated identity is not re-animated to satisfy a checklist…" |
| Closure is an event against zero | With one line open the gate prints "Exit held: USR-0091 identity, AST-0086 instrument, PO-0112 order, CLM-0071 claim, DLG-0007 delegation still open" and offers no way through; with the report empty the primary button becomes "Close exit at 18:30", the banner moves to "Exit closed", all three counters read zero and the amber bar under each tile goes with them. After closure, "Reopen the checklist" is refused — an amendment is a new record, not an edit |
| Effective-dating is visible | Moving the last working day to 20 Nov changed the banner eyebrow, the gate's date, the trail's first entry and the identity line's closing stamp in one step, and the notice states that 14 Nov stays on the record as the superseded value. The demonstration is that dependent values move together rather than one field being overwritten |
| A checked-empty line stays on the list | Project and site allocation is verified against the registers and prints "Checked empty" with nothing to click, because an exception report that shows only what it found cannot be audited for what it missed |
| Restricted records are separated by design | The gate states that payslip, appraisal and medical records are not itemised by a handover, and no personal field appears on the screen. CSV export code is implemented for fixture data, including selected records. Export controls were inspected; downloaded CSV contents and browser-specific download behavior were not independently audited. Reduced-motion styles, focus outlines, labeled controls and library interaction primitives are included; a full accessibility audit and real-device testing were not performed. The contrast and minimum-size results above are programmatic measurements against rendered styles, not a substitute for a keyboard-and-screen-reader audit.

No real authentication, data scopes, database transactions, payroll calculation, finance posting, service SLA engine, certificate generation, file scanning, external gateway, migration, backup/restore or 200-user load testing has been completed. No public deployment or external Figma upload was performed. The all-module screen plan and requirements register define future design/development coverage, not completed prototype functionality.
