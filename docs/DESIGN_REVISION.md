# Product interface revision

The user asked again for a less generic interface and a real entry page. The new direction replaces both the green editorial and cool-gray/cobalt concepts. It draws from an engineering job traveller: ink #172320, mineral paper #E6ECE6, copper #F07946, off-white records, condensed Barlow headings, Plex work text and numbered handoffs.

The bare URL now opens the intro. Its five-stop job route changes the active record and opens the corresponding module. A ruled evidence list links the BOM, purchase request, panel work order, QC gate and existing installed asset/service ticket. The dashboard starts with three decisions and linked actions. Compact totals, approvals, project relationships, inventory states, record drawers, sorting, export, column visibility, density and command search remain useful work controls.

The implementation uses [Radix primitives](https://www.radix-ui.com/primitives/docs/overview/introduction), [TanStack Table v8](https://tanstack.com/table/v8/docs/overview) and [cmdk](https://github.com/dip/cmdk), alongside Lucide and Recharts. These are actual integrations in the prototype. The [Linear design-refresh discussion](https://linear.app/now/behind-the-latest-design-refresh) informed the emphasis on predictable action placement and consistent interface chrome. This is a design inference, not a claim to reproduce Linear or SAP.

Impeccable was installed at project scope and its design hook enabled; manual rendered-page checks are also used. Superdesign was available but login returned a 502 error, so no canvas draft was created. The user-provided Graphify onboarding URL redirected to a public login view; its confident brand/task separation informed the critique, but its assets, layout and colors were not reproduced. The brief and Figma prompts use the new route-sheet direction. The original source document and C/V/D distinctions remain unchanged. Libraries support interaction behavior; product identity depends on the domain-specific screens and validation with real users.

## Making the identity actually ship

The redesign still read generic after the direction changed, so the last pass looked for the gap between the design system on paper and what the browser actually rendered. Five defects explained it. Barlow Condensed was declared in fourteen rules but never imported, so every headline silently fell back to a system face and the industrial silhouette never existed. About 620 color declarations in the base stylesheet were still inherited from the rejected cool-gray concept, including a blue progress bar and cobalt focus rings. Roughly 300 labels sat between 8 and 10 px. A single muted gray used in about 290 places measured 2.9:1 on paper. And the browser's own surfaces (selection, scrollbars, caret, placeholder, native controls, the tab color) were left at vendor defaults against a deliberately non-default palette.

The fixes were chosen so the identity is verifiable rather than asserted. The font is imported once, in `product.css`, and confirmed loaded by measuring rendered text width against the fallback. The stale colors were remapped to the mineral, record and copper ramps at matching relative luminance, which preserves every existing contrast ratio instead of trading one failure for another. Sub-11px type was raised to a hard floor. Muted text was replaced by a measured contrast ladder against each element's composited background. Browser chrome is themed from the same tokens, `theme-color` was corrected, and the brand monogram now appears as the favicon.

The second half removed things that imitate a design system without contributing to it: decorative eyebrow labels and duplicated numbering above headings on the entry cover, dispatch panel, connected-work header and service-commitments panel, plus two ambient circles on the cover. One is replaced by a drafting registration mark; the other idea moved into a scale plate in the summary column, where a decorative element could not collide with the record readout. That collision was found by measuring pseudo-element geometry, and the plate animates with the selected stop so the handoff itself moves.

Two limits worth stating plainly. One early sweep also darkened light text on the ink navigation and cover, producing dark-on-dark labels; it was reverted from an untouched copy and re-run scoped to the base stylesheet with dark-surface selectors excluded and lightness guards added, which is why the verification is presented as re-measured rather than improved. And the in-app browser in this session was fixed at a 525×553 viewport with screenshots unavailable. Rather than leave the desktop claim at that, every route was re-measured inside a same-origin iframe whose own width drives its media queries, which is how the twelve surfaces were checked at 1440×900 and 1280×800, the entry and dashboard at 1920×1080, and four surfaces at 390×844. That produced clean geometry and contrast everywhere, and it also exposed two measurement traps worth knowing: a hidden document freezes animations at time zero, so a `fill-mode: both` entrance reads as permanently invisible text until the animation is settled to its base style, and a wide table inside its own scroll container is a designed behavior, not an overflow. What remains genuinely open is a visual judgment at wide viewports; the numbers say the layout is correct, not that it looks right. The bundle told a similar story. The entry chunk went from 842 kB to 288 kB once vendor code was split out, but the charts chunk was still preloaded by the entry document, so the intro page paid for a chart runtime it never draws. The cause was two things at once: `App.tsx` imported the portal statically, and it also carried seven Recharts symbols it never used, which TypeScript did not complain about because unused-import checking was off in this config at the time. Removing the dead import and loading the operations desk behind `React.lazy` takes the charts chunk out of the entry graph entirely; the built `index.html` now references it zero times, and the dashboard arrives with its own 11 kB module. Since a lazy boundary needs a fallback worth looking at, the placeholder is drawn in the dispatch panel's ruled geometry and respects reduced motion rather than spinning.

The last sweep went after the two habits that most reliably read as generated. The first is the eyebrow label: a small uppercase kicker above a heading that says the heading again. Twenty-three of them were still in the module screens. Eleven were pure restatement ("CONTROL POINTS" over "Dispatch release controls", "REPORT CATALOGUE" over "Report catalogue", "ACCESS & ACCOUNTABILITY" over "Access administration") and are gone; the rest stayed because they hold something the heading does not, such as `WORK ORDER WO-0187` or `NOVEMBER 2026 · DRAFT RUN`. The distinction is worth keeping in mind, because the rule is not "never label above a heading", it is "never repeat one". The second habit is soft corners. The identity layer had already squared buttons, cards and navigation, but icon buttons, selects, the modal, toast, dropdown, command palette rows, textareas, pipeline columns, banners, keyboard chips, counters and progress fills still carried the previous concept's 2 to 8 pixel radii, and a system that mixes zero and six starts looking assembled rather than designed. Everything is square now except the marks that carry data. Both rules are checked by the audit page rather than remembered by eye, which is the only reason they will still be true next week.

Cleaning up after the two rejected concepts was the part that could not be done by eye at all. Two generations of styles were still shipping: the marketing landing page that was dropped for the job-traveller entry, and the generic KPI-card dashboard that was dropped for the dispatch queue. Deleting them needed a tool rather than a glance, because a class name can be built at runtime, and a stylesheet edit that quietly removes a live rule shows up as a broken screen rather than as an error. `prototype/scripts/dead-css.mjs` now decides liveness from the string literals the app can actually put into a class attribute, which is why the React state variable named `landing` does not resurrect `.landing`, while the literal prefix `grid-col-` keeps every composed `grid-col-<columnId>` alive. It removed 1,279 lines and dropped the stylesheet payload from 107.61 kB to 91.04 kB. The same run flagged six more dead symbols in the TypeScript that the compiler had been silent about, including the unused `stats()` helper that still drew the rejected KPI grid; `noUnusedLocals` and `noUnusedParameters` are on now, so those become build errors instead of dead weight. The final safety check runs in the browser rather than in the file: the audit page collects every class the rendered DOM carries and confirms each still matches a rule in the built bundle. The only unmatched ones are Lucide's own icon classes and a sidebar variant that never had a rule to begin with, so the deletion took out nothing in use. Working through the guard also surfaced one control the earlier geometry sweep had missed for a specific reason: the payroll checklist box is a `span` with a class, and a class outranks the element-level square override, so it kept its 3 pixel radius and the old concept's blue-white fill. It is square and warm now, and the circle test judges by size instead of by tag, so a 5 pixel status dot is recognised as data no matter which element someone wrote it on.

The two Inventory screens that followed (a cycle count and a subcontract reconciliation) mostly taught rules rather than adding surfaces. The first is that a status colour is a claim. Shortage, damage and variance had been rendering in the same green as Approved, because the tone function keyed on a fixed word list and nobody had ever typed "1 short" through it; the ladder is now warning words amber, settled states green, draft or locked gray, and anything still in motion the neutral teal, decided once in the regex that every badge goes through. The second is that a gate is a piece of interface, not a footnote. The maker-checker rule is demonstrated by refusing: the counter who found the variance cannot approve it, so the button stays on screen and the refusal is the response, and where the queue viewer is himself the maker the dialog drops Approve and Reject entirely and offers a hand-over instead. A prototype that quietly allowed the approval would have taught the client the wrong control. The third rule is that numbers have to be legible before they are correct: the ITM-0042 shortfall is priced as ₹85,000 rather than as two units, because two units is not something a person can approve or refuse, and the count line whose unit turned up at the QC bay and the one whose enclosure is sitting at Vector Controls both route to a transfer rather than an adjustment, which is the difference between a moved thing and a lost one. The fourth is small but shows up everywhere: put a blocked action beside a real one in a two-button footer and the pair overflows the narrow side of the grid, so the footer wraps and the blocked action keeps its own alignment. Two measurement traps came out of the same pass. Radix Tabs select on mouse down in automatic mode, so the audit harness's synthetic `click()` never left the first tab and cheerfully reported clean numbers for the wrong screen. The harness now dispatches the real sequence, and returns the active tab and the rendered heading so a silent miss cannot pose as a result. And adding two approvals to the shared queue would have made the dashboard review panel about 150 px taller than the delivery chart it sits beside, so the panel lists the three newest and its footer carries the true count; the balance between those two panels is load-bearing, and it is the kind of thing that only a measurement catches.

The last screen closes the last gap: E2E-12, the exit, which is the journey an ERP design usually draws as a form and a signature line. It was built around the fixture that was already holding company property (Priya Menon, the calibration custodian, who also owns an approved order whose delivery date lands before her last day), so the checklist points at real records instead of invented ones, and the screen's argument is about what actually closes a line. A list item is not a closing event. The instrument comes back through a custody event that names the receiver and the condition, and the tempting "mark it returned" is a refusal rather than a shortcut; the identity gets its own timestamp, and once it is deactivated the account is not switched back on to finish the paperwork, which is the same rule the inventory screens use from the other direction. Closure is an event raised against an empty exception report, so the gate refuses while anything is open and prints what is open when asked; re-dating the last working day is an amendment that moves the dependent dates and leaves the superseded one on the record; and one line (allocation) is checked and empty and stays visible, because a report that lists only its findings cannot be audited for what it skipped. Building it also caught a standing defect that had nothing to do with the exit: the tab state lands on the literal `Overview` even when the first tab is labelled something else, so content conditioned on the visible tab appeared only after clicking away and back. The visible tab is now derived once and read by both the control and the panels. The kind of thing that only shows up when you measure a landing state without clicking anything.

The reconciliation screen that followed is the last half of E2E-10, and the one place the design had been describing a rule instead of running it. It is drawn as an outbox addressed by idempotency key rather than by invoice number, because that key is what makes a duplicate posting possible or impossible: retry on the failed posting keeps BA-0051/R1 and records a fourth attempt, while "re-key it and send again" is refused, and "send it again, it is late" is refused on a send the provider has simply not answered yet. An unanswered send is not a failed send, and treating it as one is exactly how the same ₹7.20 L reaches a customer twice. A mismatch behaves the same way: BA-0049 posted ₹4,74,000 against an advice of ₹4,80,000, and the design will not let anyone mark that reconciled. The only way through is a corrected advice carrying the retention rule the first one omitted, and even then the money stays unexplained until the provider's acknowledgement is recorded, because an inbound event is the only thing that can close it. The design can write down what the provider said, it cannot invent it. "Reconciled" is therefore never stored on a posting: it is derived, and it is what a superseded record displays once its replacement has been answered, which keeps a dead posting from reading as a warning and a settled one from reading as in motion. Two things came out of measuring rather than designing. The difference tile had been clearing as soon as a correction was raised, which resolved a money exception with an act of optimism; it now waits for the acknowledgement, and the re-send refusal keys off the amount instead of the row count. And `white-space: nowrap`, which is right for a record grid where a row is a line you scan across, was quietly pushing the argument cells of the journey tables past their own scroll container (409 px on the outbox, 305 on the exit checklist) while the audit called it clean, because scrolling inside an ancestor is a designed behaviour. Those tables now wrap, with each column's width stated so the scan order survives the wrap and a floor of 720 px so a narrow screen hands the remainder to the scroll container instead of crushing the text. It is worth recording as the failure mode it is: a measurement rule that stops at the edge of a component will certify a layout that no one can read.
